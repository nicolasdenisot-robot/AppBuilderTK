03Two starting points

Start fresh — or from an app you already have

You don't have to begin from zero every time.

From scratch

Answer the interview and it builds a brand-new app for your outcome.

From existing code

Point it at code you already have — even from elsewhere. It reads it, works out what it does, and writes a plain-language overview. Same for scoping a change to a working app.

04The spec

Every app carries its own spec

One document per app — DIRECTIVE.md — the single source of truth for how it should behave.

  • Written during the interview — your answers become the specification.
  • A living document — it grows as the app is built, never thrown away.
  • Records lessons as they happen — quirks, settings, and fixes are captured.
  • The next session and the next app both benefit from what was learned.

10Under the hood

Two ways to reach NVGate — with firm guardrails

Layer A

Live control

Drive a running analyzer in real time — run/stop, change settings, fetch live results.

NVGate must be open & connected
Layer B

File access

Read and process saved signals & results on disk — offline, with NVGate closed.

No analyzer required
  • It looks commands up — it never guesses them. OROS ships its manuals as machine-readable data: every NVDrive command, every setting identifier, every error code. Wrong command names are the fastest way to a broken app, so nothing is recalled from memory.
  • Your data is protected — measurements & settings are never overwritten; changes go to new, dated copies.
  • It confirms before touching your machine, and speaks plain language throughout.
